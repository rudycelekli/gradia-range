# ADR-010: Open-source cohort before enterprise twins

- **Status**: proposed
- **Date**: 2026-10-24
- **Deciders**: Rudy Celekli
- **Tags**: cohort, twenty, sequencing
- **Recall**: 2026-10-24 decision consult returned not-adopted. History is UNKNOWN. No project memory db.

## Context

Enterprise twins need a private room, an identity map, a written scope, and a buyer who can look at evidence. We have the brand sheet and the accepted-work ledger. We do not yet have a Range witness in production. Open-source projects let us boot twins from public code, report to a real maintainer, sell a real fix, and fill a free board. Twenty is the example already named. It can run on a synthetic workspace.

## Decision

Phases 1 through 5 use the open-source cohort only. Twenty is the first twin. A project joins when we can boot it, load synthetic data, name a disclosure contact, and publish at least one atom with a machine-checkable win condition. The proposed list of 20 lives in the plan. Membership is recorded per project when the join rule is met.

Enterprise private twins start at phase 6, after one Open Board, one external-solver path, and one lab drop exist. Axiom may talk to enterprises earlier. Accepting a private twin before phase 6 means superseding this ADR.

House solvers do the attempts and the fixes through phase 3. External solvers enter at phase 4, on the Open Set first.

## Consequences

### Positive

- The first system under test is a public codebase we can show.
- Fix revenue can start from Axiom's existing service motion.
- The free board has real tasks behind it.
- Enterprise conversations, when they start, can point at a board and a disclosure record.

### Negative

- Maintainer revenue is lumpy and often zero. The cohort is a proof and a corpus seed.
- Twenty is large. Phase 1 is one atom, one chain, one campaign skeleton, one report, and one fix offer.

### Neutral

- The proposed 19 beside Twenty can change without a new ADR. Changing the order, cohort before enterprise, means superseding this one.
