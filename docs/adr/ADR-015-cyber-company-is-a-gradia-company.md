# ADR-015: The cyber practice is a Gradia company

- **Status**: proposed
- **Date**: 2026-10-24
- **Deciders**: Rudy Celekli
- **Tags**: company, brand, cybersecurity
- **Recall**: 2026-10-24 decision consult returned unavailable. History is UNKNOWN. Global Ruflo was unavailable.

## Context

Gradia is the evaluation lab. AxiomConsulting.ai is already a Gradia company, and it implements work that is not this practice. Buyers of a security engagement need one company whose only job is the twin, the Harbor tasks, the severity report, the fix, and the benchmark. Putting that invoice through Axiom, or through Gradia itself, makes the buyer hire an implementation arm or a workflow lab for a security job.

The tasks are still Gradia tasks in the technical sense. Harbor can load them. Gradia can run them as agent evaluations. That reuse is how one task serves the board, the lab, and the security buyer. The company that owns the task wins that market even when a different solver reaches the objective.

The legal name has not been chosen.

## Decision

Cybersecurity is a new company. It is a Gradia company in the same sense as AxiomConsulting.ai: its own buyers and its own invoice, using Gradia's language, witness rule, and Harbor tasks.

- Scope is security only. Workflow evaluations stay Gradia's product. This company may introduce that work. It does not contract it.
- This company owns the security task set, the board, the report, and the fix engagement.
- Gradia may run published tasks as evaluations. The lab license in [ADR-008](ADR-008-traces-leave-after-the-fix-window.md) still governs traces that leave.
- A house attempt is labeled house. The company is the operator, not a row on the solver board.
- The company wins by owning the task: one Harbor task is the board entry, the Gradia eval item, and the shape of the enterprise engagement. A collaborator who reaches `objective` is credited on the witness. The task and the customer remain this company's.
- The legal name is unset. Documents say "the cyber company" until a name is chosen. The public repository stays [gradia-range](https://github.com/rudycelekli/gradia-range) until that name exists.
- This decision replaces the sentence in [ADR-001](ADR-001-range-is-a-gradia-product.md) that sends the security invoice through Axiom. It narrows [ADR-012](ADR-012-security-first-workflows-on-the-same-twin.md): this company does not emit a workflow family.

Public trust remains Rudy Celekli's contribution ledger and Gradia as the lab. The cyber company is the name on the security contract.

## Consequences

### Positive

- A security buyer gets a company that does only that.
- Gradia can use the tasks without this company becoming the workflow lab.
- The win condition is ownership of the task set, so a collaborator's solve still benefits the company.

### Negative

- A second company costs a name, a site line, and a contract template before there is revenue.
- Until the name exists, public copy has to say "a Gradia company" and point at the Range repository.

### Neutral

- Axiom is unchanged. It keeps Gradia's non-cyber implementation work.
